# Maestro Router v0.1.0-rc.1

Esta versão é uma **pré-release para avaliação técnica**. Estas notas foram preparadas para a futura publicação; esta worktree não criou tag Git nem GitHub Release, e a publicação ocorrerá somente após merge aprovado e revalidação posterior.

## Propósito e público

O Maestro Router v0.1.0-rc.1 é destinado a desenvolvedores, arquitetos de software e operadores que desejam avaliar localmente um núcleo open source de roteamento econômico, determinístico e explicável entre modelos de inteligência artificial.

Esta versão serve para inspeção arquitetural, testes de integração local e validação conceitual do pipeline de decisão e execução. Não é recomendada para ambientes de produção.

## Distribuição e execução

A distribuição desta pré-release é feita exclusivamente como código-fonte por meio do repositório no GitHub. Não há pacote publicado no PyPI.

A avaliação é realizada via clonagem do repositório e execução local utilizando **Python 3.12**. Para instruções detalhadas de configuração de ambiente virtual, instalação de dependências e comandos de inicialização, consulte o [README.md](../../README.md).

## Capacidades implementadas no MVP

As capacidades a seguir estão implementadas no código e validadas pela suíte de testes automatizados, conforme documentado no [README.md](../../README.md) e no [SYSTEM-MAP.md](../maps/SYSTEM-MAP.md):

- **Validação pública**: validação rigorosa de requisições em `POST /v1/executions` com schemas fechados e recusas normativas (`INVALID_REQUEST`).
- **Elegibilidade não econômica**: aplicação de filtros de capacidades, critérios de qualidade, allowlist e disponibilidade antes de qualquer avaliação de custo, com recusa normativa `NO_ELIGIBLE_ROUTE`.
- **Avaliação econômica prévia**: verificação de estimativas e múltiplos tetos econômicos cumulativos antes da seleção, com recusa normativa `INSUFFICIENT_ECONOMIC_INFORMATION` quando a decisão de custo for inviável.
- **Seleção determinística**: estratégia de menor custo estimado (`lowest-estimated-cost`) com comparação decimal exata e desempate determinístico por identificador de rota (`route_id`).
- **Fronteira neutra de execução**: desacoplamento entre decisão e execução, acionando exatamente uma rota selecionada via adaptador associado em memória.
- **Adaptador externo OpenAI Responses API**: suporte inicial para execução com a API de Responses da OpenAI via cliente assíncrono oficial injetado explicitamente.
- **Composição operacional OpenAI**: suporte a modo de rota única (legado) e modo multirrota configurado via variáveis de ambiente com validação estrita de integridade estrutural no bootstrap.
- **Restrições operacionais de roteamento**: configuração de restrições globais do operador com composição monotônica junto às restrições da requisição (ADR 0009).
- **Indisponibilidade e habilitação operacionais**: declaração explícita de indisponibilidade conhecida (`known_unavailable`, ADR 0010) e habilitação de rotas (`enabled`, ADR 0011) sem chamadas de rede externas.
- **Uso e custo normalizados**: normalização de tokens observados (`input_tokens`, `output_tokens`) em estados neutros (`available`, `uncertain`, `unavailable`) e cálculo posterior de custo decimalmente exato quando há referência tarifária completa.

## Limitações e escopo atual

Para manter expectativas alinhadas e transparentes, observe as limitações deste estágio:

- **Sem rota, provedora ou modelo padrão**: não há roteamento automático para provedores não configurados; rotas e modelos devem ser explicitamente definidos pelo operador.
- **Sem gestão de credenciais integrada**: chaves de API e credenciais devem ser fornecidas externamente via ambiente de execução.
- **Sem preços padrão ou consulta dinâmica**: não há tabela embutida, scraping ou atualização automática de preços; referências tarifárias e previsões de uso devem ser informadas pelo operador.
- **Sem resiliência de rede avançada**: não há timeout concreto configurável, retry automático ou fallback entre rotas nesta versão.
- **Único adaptador externo implementado**: apenas a OpenAI Responses API possui adaptador externo no momento; outros adaptadores dependem de extensão manual do contrato neutro.
- **Fora do escopo do MVP**: agentes autônomos, memória persistente de conversação, orquestração de múltiplos modelos em grafo e workflows complexos não fazem parte desta versão.
- **Estimativas e custos calculados não são billing**: os valores de estimativa pré-execução e custo calculado destinam-se exclusivamente à tomada de decisão e explicabilidade; não constituem fatura, cobrança financeira nem comprovação de economia entre provedores.
